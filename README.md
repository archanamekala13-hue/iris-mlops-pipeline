# Iris Neural Network – MLOps Pipeline (MLflow + FastAPI + Docker + Render)

## What is in this project
| File | Purpose |
|---|---|
| `iris.csv`, `create_dataset.py` | Dataset (150 rows) and the script that created it |
| `neural_network.py` | Your original standalone neural-network script |
| `train.py` | **Pipeline step:** train, evaluate, log to MLflow, save `model.joblib` + `metrics.json`. Fails if test accuracy < 100% |
| `main.py` | FastAPI app (`/`, `/health`, `/metrics`, `/predict`) loading the MLflow model |
| `test_app.py` | pytest tests for the API and the accuracy |
| `Dockerfile`, `.dockerignore` | Docker image (trains the model while building) |
| `render.yaml` | Render Blueprint (Docker service) |
| `.github/workflows/ci.yml` | GitHub Actions: train -> test -> docker build on every push |

Accuracy: test = 100% (30 samples), training = 98.33% (120 samples).

## Step-by-step (Windows / PowerShell; same commands work on Mac/Linux)

### Step 1 - Extract and open the folder
Extract `iris-mlops.zip`, then:
```
cd iris-mlops
```

### Step 2 - Run it locally (Python 3.11 or 3.12)
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python train.py
pytest -v
uvicorn main:app --reload
```
`train.py` must print `Test accuracy: 100.00%` and `SUCCESS`. Open http://127.0.0.1:8000/docs
and try **POST /predict** with
`{"sepal_length":5.1,"sepal_width":3.5,"petal_length":1.4,"petal_width":0.2}` -> `setosa`.

Optional - view the MLflow experiment UI: `mlflow ui --backend-store-uri ./mlruns` -> http://127.0.0.1:5000

### Step 3 - Build and run the Docker image
Install and start Docker Desktop, then:
```
docker build -t iris-mlops .
docker run --rm -p 8000:8000 iris-mlops
```
Open http://localhost:8000/docs . (Training runs during `docker build`; the build fails if test accuracy is below 100%.)

### Step 4 - Push to GitHub
1. On github.com create a **new empty repository** (e.g. `iris-mlops-pipeline`, no README/.gitignore).
2. In the project folder:
```
git init
git add .
git commit -m "Iris MLOps pipeline with Docker"
git branch -M main
git remote add origin https://github.com/<your-username>/iris-mlops-pipeline.git
git push -u origin main
```
(If the repo already exists with old files: `git push -u origin main --force`.)
3. Open the **Actions** tab - the CI workflow should turn green.

### Step 5 - Deploy on Render
1. Sign in at https://render.com with GitHub.
2. **New +** -> **Web Service** -> select your repository -> **Connect**.
3. Set **Language / Runtime = Docker** (Render finds the `Dockerfile`). Pick the **Free** instance type.
4. Under **Advanced** set **Health Check Path** to `/health`.
5. Click **Create Web Service** and wait for the build (a few minutes).
   *Alternative:* **New +** -> **Blueprint** -> pick the repo; Render reads `render.yaml`.
6. Open your URL `https://<service-name>.onrender.com/docs` and test `/predict`.

### Step 6 - Redeploy after changes
```
git add .
git commit -m "your message"
git push
```
Render auto-deploys every push to `main`.

## Notes
- Free Render services sleep after ~15 min idle; the first request afterwards takes about a minute.
- `mlruns/`, `model.joblib` and `metrics.json` are generated by `train.py` and are git-ignored on purpose
  (MLflow stores absolute local paths, which break on other machines). Render/Docker regenerate them at build time.

## Monitoring

The API now exposes these monitoring endpoints:

| Endpoint | What it gives you |
|---|---|
| `/health` | Liveness check (used by Render) |
| `/monitoring/summary` | JSON: predictions served, species mix, model accuracy, **data-drift check** |
| `/monitoring/metrics` | Prometheus metrics: request rate, latency, errors, predictions by species, input feature distributions, model accuracy |

Every prediction is also written to the logs as one JSON line (visible in the Render **Logs** tab and `docker logs`).

### A. Quick check (no extra tools)
```
python send_traffic.py http://localhost:8000 60          # normal traffic
python send_traffic.py http://localhost:8000 80 --drift  # shifted inputs -> status "DRIFT"
```
Then open http://localhost:8000/monitoring/summary

### B. Prometheus + Grafana dashboard (local, needs Docker)
```
docker compose -f docker-compose.monitoring.yml up --build
```
- API: http://localhost:8000/docs
- Prometheus: http://localhost:9090 (Status -> Targets should show `iris-api` UP)
- Grafana: http://localhost:3000 (login `admin` / `admin`) -> Dashboards -> **Iris API Monitoring**
- Generate traffic: `python send_traffic.py http://localhost:8000 200`
- Stop: `Ctrl+C`, then `docker compose -f docker-compose.monitoring.yml down`

### C. Monitoring the deployed Render service
1. Render dashboard -> your service -> **Logs** (prediction lines) and **Metrics** (CPU, memory, HTTP).
2. Uptime alerts: create a free monitor at https://uptimerobot.com (HTTP(s), URL `https://<service>.onrender.com/health`, 5-minute interval, email alert). This also keeps the free instance from sleeping.
3. Model/drift view: `https://<service>.onrender.com/monitoring/summary`
